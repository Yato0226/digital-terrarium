\title{\textbf{Autonomous Digital Terrarium: An AI-Director Multi-Agent Ecosystem with Hosted Open-Weight Models on a Minimal Container}}
\author{\href{https://github.com/Yato0226}{github.com/Yato0226}}
\maketitle

\begin{abstract}
Running persistent LLM applications on a small home server requires keeping host RAM and compute footprints minimal without sacrificing model capability. This paper demonstrates the implementation of an autonomous multi-agent ecosystem (``Digital Terrarium'') running continuously in a low-resource environment. All language-model work is offloaded to Google's hosted Gemini API, which serves the open-weight Gemma 4 family: a 31B dense model (\texttt{gemma-4-31b-it}) as the primary narrator with automatic fallback to the 26B MoE variant (\texttt{gemma-4-26b-a4b-it}), so the host needs only a 2~GB LXC container on a Proxmox VE hypervisor and no local inference hardware. The system adopts an \emph{AI Director} pattern: the LLM proposes behavioural intent for each agent, while a deterministic Python engine owns all state consequences. Per-tick, \texttt{schema.py} rebuilds a Pydantic model from the current active-agent roster, embedding one \texttt{AgentDecision} field per pawn with \texttt{action}, \texttt{narrative}, \texttt{quote}, \texttt{inner\_monologue}, \texttt{direction} (for Move), \texttt{target} (for Attack/Share/Mate, built from \texttt{Literal[tuple(pawn\_ids)]} per PEP 586 Python 3.10 compatibility), a free-form \texttt{flavor} verb (for the open-ended \texttt{Interact} action), a \texttt{new\_goal} wish the engine may adopt into a tracked personal goal, and a \texttt{new\_title} for earned dynamic roles. This schema is passed to the Gemini API as a structured-output schema (\texttt{response\_schema}), which both forces valid JSON and suppresses the model's reasoning channel. The response is validated again with Pydantic, and any failed parse skips mutation and increments the tick. Any \texttt{!order} placed by the god replaces the LLM's proposed action for that agent, Python enforces it, and the LLM merely narrates. The world is exposed through a Discord bot that lets a ``god'' spawn agents, edit stats, and issue enforced orders. With the model no longer resident on the host, memory is flat and Out-Of-Memory (OOM) faults are structurally impossible; daily quota headroom, structured-output reliability, and coherent agent interactions are evaluated over extended runs.
\end{abstract}

\section{Introduction}
Running persistent LLM applications in edge environments requires strictly balancing parameter size, context management, and host system RAM allocation. Unconstrained context windows or pure text generation often result in state hallucination, numerical drift, and memory exhaustion.

This paper outlines the architecture and deployment of an autonomous ``Digital Terrarium'', a multi-agent ecosystem driven by periodic tick-based LLM calls. A key design decision is the separation of \emph{intent} from \emph{consequence}: the LLM decides what each agent \emph{wants} to do, and a deterministic engine (pure Python) validates, costs, and applies the resulting effects. Because the model never emits stat deltas, the LLM cannot corrupt the simulation; it operates strictly as the narrator and decision-maker. A novel contribution is the combination of (i) a per-tick rebuilt output schema derived from the live agent roster, and (ii) a ring buffer of structured events that lets agents react to recent history without exploding the context window. A Discord-based ``god'' interface further allows a human operator to intervene: spawning agents, editing attributes, and issuing enforced orders that override model behaviour.

The system is a single Python process split into focused modules: \texttt{state.py} (world state and persistence), \texttt{schema.py} (per-tick LLM output models), \texttt{prompts.py} (system prompt and prompt builder), \texttt{llm.py} (hosted Gemini API client with primary/fallback models), \texttt{engine.py} (deterministic rules), \texttt{events.py} (structured event log), \texttt{map\_renderer.py} (pure-Python PNG map writer), \texttt{core.py} (tick orchestration and scheduler), and \texttt{bot.py} (Discord god interface). A companion zero-dependency server, \texttt{feed.py} (hand-rolled RFC 6455 WebSocket plus static HTTP on asyncio, no third-party websocket library), broadcasts a compact JSON snapshot after every completed tick to a vanilla HTML/CSS/JS client that renders the world as a floating isometric diorama in a browser: the 5$\times$5 grid becomes a cutaway island, standing pixel-art pawn sprites (sex/elder/child variants, idle and walking strides) and fauna/visitor/raider sprites (legendary beasts tinted dark) interpolate their tile walks in the first seconds of each tick, pawns on the same tile fan out in a stable diamond formation with hover name pills, speech and private thoughts land as colour-coded rows in a bottom-right chat box instead of floating bubbles, looping action animations and atmospheric particles (a four-frame campfire flame, smoke, river shimmer, swaying trees, drifting snow in winter and a warm radial glow around camp at night) carry the rest of the tick, and status emotes react to per-tick events. A HUD keeps the view informative: a wooden-banner top bar tracks season, weather, day/night, the colony's wood/food/stone/fiber stockpiles and campfire/shelter percentage gauges (with frost edging in winter); a colonist roster drawer shows each pawn's pixel portrait with mini health/energy bars and current action; a bottom narrative log scrolls the latest event descriptions, highlighting AI-Director prose with an accent rail; clicking a pawn opens a dossier card with vitals, gear, rucksack contents, skills, the active goal, relationships and lineage; and a lore panel browses graveyard epitaphs, Monolith runes, the seasonal chronicle and Architect patch notes. All of it is fed by the broadcast snapshot (\texttt{resources}, per-pawn dossier fields, and a \texttt{lore} payload), so the client stays read-only and the engine is untouched. The client renders everything procedurally --- pixel-art sprites from hand-authored string grids and seeded textures, upscaled with nearest-neighbour scaling and no external assets --- so it stays offline with no asset footprint or runtime downloads. The data flow per tick is:

\begin{enumerate}
\item \textbf{Schema rebuild}: \texttt{schema.py} constructs a Pydantic model containing one decision field per \emph{active} agent, plus optional \texttt{quote}, \texttt{inner\_monologue}, and Move \texttt{direction} fields, a \texttt{target} literal built from the current roster, a \texttt{flavor} verb for Interact, and fields for personal goals and custom titles. Adding or removing agents therefore requires no manual schema edits.
\item \textbf{Decision}: the LLM is prompted with current vitals, skills, personality, relationships, gear, map positions, and the event ring buffer. The per-tick Pydantic schema is passed to the API as a structured-output schema (\texttt{response\_schema}) that both forces valid JSON and suppresses the model's reasoning channel; the response is validated again with Pydantic, and a failed parse skips mutation and increments the tick.
\item \textbf{Intent override}: any \texttt{!order} placed by the god replaces the LLM's proposed action for that agent, Python enforces it, and the LLM merely narrates.
\item \textbf{Deterministic resolution}: \texttt{engine.resolve\_actions()} validates the intent (energy cost, target legality), computes consequences (damage, resources, skill XP, relationship deltas), and emits structured events.
\item \textbf{Save inside lock}: \texttt{terrarium\_state.json} is persisted (auto-migrated on startup), the tick counter is incremented, and the tick lock is released. Then the best-effort eulogy LLM generates tombstone inscriptions for the newly fallen (posted immediately as dedicated eulogy embeds), and a Discord state embed is posted outside the lock only on high-impact ticks (season change, death, birth, feast, quest completion, or a crisis such as a raid, wildfire, flood, or miasma) so quiet ticks do not spam the channel.
\end{enumerate}

Agent state is intentionally rich and nested: \texttt{vitals} (HP, energy, hunger, warmth, morale), \texttt{skills} (woodcutting, scouting, combat), \texttt{personality}, \texttt{inventory} (wood, food, stone, fiber), \texttt{gear} (main hand / body equipment), \texttt{counters} (lifetime deeds such as trees felled and blizzards survived), a \texttt{title} epithet recomputed from those counters each tick, \texttt{relationships}, a \texttt{pos} coordinate on a shared $5\times5$ map, and \texttt{status} (active / incapacitated / dead). Two deterministic layers add psychological texture: \texttt{traits} are rolled once at spawn/birth (Night Owl, Brawler, Pyromaniac, Pacifist, Iron Stomach) and their effects live entirely in the engine --- cheaper night actions, unarmed damage, fires, forage yields, slower hunger --- never in the LLM output; and \texttt{moodlets} are transient episodic morale drains (Grief when a survivor dies, Frostbitten when warmth hits zero) that decay by one tick per simulation tick and sum into net morale, so grief can tip an agent toward a mental break. A shared \texttt{biome} block holds the world: season (rolled every 100 ticks, Figure~\ref{fig:seasons}), weather, a 20-tick day/night cycle, campfire and shelter integrity, depletable wood/food stocks that regrow every tick except in Winter, and the map tiles themselves. A lit campfire warms only agents within one tile of the Camp tile; shelter warmth is global. Reaching 0 HP incapacitates an agent; it is excluded from LLM decisions and auto-recovers 10 HP per subsequent tick. Environmental permadeath is reserved for freezing in a Blizzard (warmth reaches 0), starvation beyond five consecutive starving ticks, or reaching old age (\texttt{OLD\_AGE\_MAX} = 320 ticks = 16 days): the agent is removed from the roster and enshrined in the \texttt{graveyard} with its final epithet, cause, and a tombstone. Psychological pressure is a real mechanic: morale below 20 is a breakdown risk, morale at 0 triggers a deterministic \emph{mental break} (berserk rampage, paranoid hiding, apathetic wandering, or a pyromaniac's firesetting) that overrides all agency for three ticks, and morale above 80 grants a $+10\%$ gathering bonus. The world also hosts a small \texttt{wildlife} population of deterministic non-agent entities --- prey (Deer, Rabbit) flee the nearest agent and predators (Wolf, Bear) stalk the agent furthest from Camp and bite only to incapacitate, never kill, consistent with combat. Hunting converts a kill directly into food and fiber (no intermediate resource), and an agent can tame same-tile prey into a camp pet that lifts the whole colony's morale; a built granary stops Summer food decay and a palisade level deters predators. All action effects are listed in Table~\ref{tab:actions}; the LLM's schema contains \emph{no} numerical fields.

Beyond the colonists, the world itself is alive. \texttt{world\_state} hosts the colony and the systems around it --- wildlife, wandering visitors, hostile raiders, emergent culture, and the Architect that re-balances the world each year. Figure~\ref{fig:systems} maps every system to its engine-owned consequences; Table~\ref{tab:stages} shows how they arrived stage by stage. The invariants that matter: kills convert to \texttt{food} and \texttt{fiber} (no ``meat'' resource); predators bite only to incapacitate, never kill; \texttt{Interact} verbs are bucketed by keyword with scouting/sociability-scaled rolls (taming $0.5+0.02\cdot\texttt{scouting}$, recruitment $0.3+0.05\cdot\texttt{sociability}$); tradition tags are sticky once earned; raid plunder is capped at 5 food; and every Architect delta is clamped to $[0.7, 1.3]$ before it touches the world. The ecology is reactive: with no wild predator left alive the prey cap rises from 3 to 5, and each surplus herd strips wild forage from \texttt{food\_stock} and may eat ripe farm plots, so over-hunting predators trades short-term safety for a slow-burn famine; and cutting the Forest down to at most 6 tiles removes the windbreak, adding \texttt{WINDBREAK\_COLD\_PENALTY} to Winter cold and roughly doubling the Spring flood chance. Colonists therefore have reason to spare a wolf or two. A predator that survives mauling \texttt{LEGEND\_INJURY\_MIN} colonists is likewise worth remembering: it earns a permanent name (\emph{The Grey Terror}, \emph{Old Scar-Face}), double HP, and a fame score that sharpens its bite; the whole colony carries a \texttt{Legend Hunt} moodlet, the beast withdraws at each season change only to return more infamous (escapes add fame), and slaying it is a colony-wide celebration (\texttt{LEGEND\_SLAY\_MORALE}). The world also hides its edges: the 16 outer rim tiles start wrapped in mist until a Scout stands within two tiles of them, so the perimeter must be actively mapped (a fully mapped rim lifts the mist and pays \texttt{MAPPED\_MORALE}); and a pair of colonists at the rim can pack \texttt{EXPEDITION\_RATIONS} and leave the grid for 15--20 ticks, returning with loot, an exotic seed that tills a new farm plot, a tamed companion, or battle scars (a \texttt{scars} counter). Nature is also capable of long trials: at each season change a cataclysm may descend for \texttt{CATACLYSM\_CHANCE} of the time and persist for 150 ticks. \emph{The Long Winter} adds \texttt{LONG\_WINTER\_COLD} to every pawn's cold and doubles the campfire's wood appetite (\texttt{LONG\_WINTER\_FUEL\_MULT}); \emph{The Great Drought} dries the rivers (river foraging fails with a \texttt{drought} feasibility reason) and doubles lightning and fire-spread danger (\texttt{DROUGHT\_FIRE\_MULT}). Both end when \texttt{ends\_tick} passes, and each is surfaced to the LLM as a trial to endure. What a colony survives becomes its name: surviving wildfire, famine, floods, cataclysms, or founding a way of life stamps an earned landmark (\texttt{colony.earned}) and rebrands the colony by priority --- \emph{The Ashen Kin}, \emph{The Famineborn}, \emph{The Hearthfolk}, \emph{The Kindred} --- with the old name kept in \texttt{colony.history} and a \texttt{colony\_renamed} event. Traumas also seed taboos: when a colonist dies on the ruins tile, the colony records a \texttt{ruins} taboo and low-bravery colonists (bravery $\le$ \texttt{RUINS\_FEAR\_BRAVERY}) refuse to move onto that ground unless a god orders it, failing with a \texttt{taboo} feasibility reason. The god's own whispers (\texttt{!say}) shape faith: three whispers to the same colonist earn the \textbf{Prophet} mantle (steady morale and a \texttt{the Prophet} title), and a Prophet's sermon (\texttt{Interact} ``preach''/``sermon'' at camp) lifts every colonist on the tile and builds regard toward them. Once the Ancestral Monolith stands (the camp fully fortified), the colony may raise a small shrine (a \texttt{shrine\_built} event, 3 wood + 2 stone) and leave food offerings at it (\texttt{Interact} ``offer''; a Prophet's tithe counts double); once \texttt{SHRINE\_BLESSING\_OFFERINGS} offerings are banked the Creator blesses the whole colony (\texttt{Blessed} moodlet, \texttt{SHRINE\_BLESSING\_MORALE}) and the shrine becomes consecrated, halving the next cataclysm's chance (\texttt{SHRINE\_CATACLYSM\_MULT}). Memory becomes material: every landmark the colony survives --- a cataclysm, a slain legend, the Monolith raised, a shrine blessing --- is stored as \texttt{world\_state["last\_milestone"]}, and an artisan at camp can \texttt{Interact} ``carve a totem'' (2 wood, up to \texttt{TOTEM\_MAX}) to fix it in wood, gifting every colonist a ``Proud of the landmark'' moodlet that outlives the generation that earned it. Foragers turn the meadows to medicine: \texttt{Interact} ``gather herbs'' on a meadow banks a salve (\texttt{counters.salves}), and at camp \texttt{Interact} ``brew salve''/``heal'' nurses the most-injured colonist on the tile back toward health (\texttt{SALVE\_HEAL} HP, clearing the \texttt{Frostbitten} moodlet).

\subsection{Discord ``God'' Interface}
Beyond the one-way webhook embeds, a two-way Discord bot (prefix \texttt{!}) exposes a god layer that manipulates the world directly (Table~\ref{tab:god}). Commands that mutate \texttt{world\_state} are serialised against the tick loop via an \texttt{asyncio.Lock}, and a \texttt{!pause}/\texttt{!resume} pair gates the scheduler. Enforced orders (\texttt{!order}) are injected into the prompt and overridden in code; whispers (\texttt{!say}) are injected into the prompt \emph{and} grant a deterministic $+15$ morale, letting the Creator pull an agent out of a mental break. Human watchers (not just the god) can also adopt a pawn from any channel via \texttt{!adopt} --- the mapping persists, \texttt{!my} shows the adopted ward, \texttt{!unadopt} releases it, and milestone events (birth, fulfilled goal, mental break, death) are delivered to the adopter as a direct message over the gateway, routed through a notifier hook (\texttt{core.notifier}) that \texttt{bot.on\_ready} registers, so \texttt{engine.py} stays free of Discord logic.

\subsection{Implementation Code}
Listing~\ref{lst:schema} shows the per-tick dynamic schema; Listing~\ref{lst:engine} the deterministic resolution core; Listing~\ref{lst:tick} the tick orchestration. Together they implement the AI Director pattern. Note that \texttt{Literal[tuple(pawn\_ids + wildlife\_ids + visitor\_ids + raider\_ids)]} is used deliberately: on Python 3.10 the starred \texttt{Literal[*ids]} unpacking form is unavailable, and the tuple form is equivalent per PEP~586.

\begin{lstlisting}[style=python, caption={Dynamic LLM Output Schema (schema.py, condensed). Uses \texttt{Literal[tuple(pawn\_ids + wildlife\_ids + visitor\_ids + raider\_ids)]} for Python 3.10 compatibility (PEP 586)}, label={lst:schema}]
def build_models():
    pawn_ids = [pid for pid, p in world_state["pawns"].items()
                if p["status"] == "active"]            # roster-aware
    target_ids = (pawn_ids
                  + [w["id"] for w in world_state["wildlife"]]
                  + [v["id"] for v in world_state.get("visitors", [])]
                  + [r["id"] for r in world_state.get("raiders", [])])
    AgentDecision = create_model(
        "AgentDecision",
        action=(Literal["Chop", "Rest", "Scout", "Attack", "Forage", "Build",
                        "Share", "Move", "Mate", "Interact", "Expedition"],
                Field(description="Intent")),
        narrative=(str, Field(description="1-2 sentence narrative")),
        quote=(Optional[str], Field(default=None, description="Outward speech")),
        inner_monologue=(Optional[str], Field(default=None,
                                              description="Private thought")),
        direction=(Optional[Literal["N", "S", "E", "W"]], Field(
            default=None, description="Direction - only for Move")),
        target=(Optional[Literal[tuple(target_ids)]], Field(
            default=None, description="Target id (pawn/wildlife/visitor/raider)")),
        flavor=(Optional[str], Field(default=None,
                                     description="Free-form verb - only for Interact")),
        new_goal=(Optional[str], Field(default=None,
                                       description="Personal goal wish when goal-less")),
        new_title=(Optional[str], Field(default=None,
                                        description="Earned custom role/title")),
    )
    fields = {"world_event": (str, Field(description="Global status summary"))}
    for pid in pawn_ids:                               # one field per active pawn
        fields[pid] = (AgentDecision, Field(description=f"Decision for {pid}"))
    return create_model("TickResponse", **fields)
\end{lstlisting}

\begin{lstlisting}[style=python, caption={Deterministic Resolution (engine.py, condensed). Applies action $\to$ consequences: energy costs, combat, skill XP, relationships, incapacitation, crafting, mental breaks, environmental death, Mate, free-form Interact, personal goals, traits, moodlets, fauna (hunt/tame, granary, palisade), visitors (barter, plunder, recruit), scavenger raids (steal, defend, flee), megaprojects (monument), farm plots (till/grow/harvest), emergent traditions (counters $\to$ Tradition Tag), solstice feasts \& funerary rites (Grief halving), wildfires, seasonal disasters, Stage 9 synthesis (custom recipes, quests, clamped balance modifiers), trophic cascades \& legendary beasts, fog of war \& off-grid expeditions}, label={lst:engine}]
def resolve_actions(intents):
    for pawn_id, intent in intents.items(): # (action, target, flavor, new_goal, new_title)
        pawn = world_state["pawns"][pawn_id]
        action, target, flavor = intent[0], intent[1], intent[2]
        cost = ACTION_COSTS[action]   # Chop 10, Scout 15, Move 5, Interact 5, Expedition 15
        if "Night Owl" in pawn["traits"] and not is_day():
            cost //= 2                # night owls act cheaply after dark
        if pawn["vitals"]["energy"] < cost:        # engine refuses intent
            add_event("failed", reason="low_energy")
            continue
        pawn["vitals"]["energy"] -= cost
        if action == "Rest":
            pawn["vitals"]["hp"] += 10
        elif action == "Chop":
            if tile_at(pawn) not in FOREST: add_event("failed"); continue
            wood = min(biome["wood_stock"], 3 + pawn["skills"]["woodcutting"] // 3)
            if pawn["gear"]["main_hand"] == "Stone Axe": wood *= 2
            biome["wood_stock"] -= wood            # forest is depletable
            pawn["inventory"]["wood"] += wood
        elif action == "Move":
            if not in_bounds(pos + DIRS[target]):
                add_event("failed", reason="off_grid"); continue
            pawn["pos"] += DIRS[target]            # tile-gated world
        elif action == "Forage":
            if tile_at(pawn) not in (MEADOW, RIVER): add_event("failed"); continue
            food = min(biome["food_stock"], 2 + pawn["skills"]["scouting"] // 4)
            biome["food_stock"] -= food; pawn["inventory"]["food"] += food
        elif action == "Build":
            if pawn["inventory"]["wood"] < 3:
                add_event("failed", reason="need_wood"); continue
            if craft := best_affordable_tool(pawn):  # Stone Axe, Flint Spear, Warm Coat
                give_gear(pawn, craft); add_event("craft", item=craft); continue
            biome["shelter"] = min(100, biome["shelter"] + 8)
        elif action == "Share":
            if not legal_target(target): add_event("failed"); continue
            if target in VISITOR_IDS:    # barter with a visiting traveler
                pawn["inventory"]["food"] -= 2
                gained = min(3, visitor["inventory"]["stone"])
                pawn["inventory"]["stone"] += gained
                add_event("barter", kind=visitor["kind"], gains=gained); continue
            pawn["inventory"]["food"] -= 1
            world_state["pawns"][target]["inventory"]["food"] += 1
        elif action == "Attack":
            if not target or target == pawn_id: add_event("failed"); continue
            if target in WILDLIFE_IDS:     # hunt: damage animal; kill yields food+fiber
                dmg = max(1, 5 + pawn["skills"]["combat"] // 2)
                animal = wildlife[target]; animal["hp"] -= dmg
                if animal["hp"] <= 0:
                    pawn["inventory"]["food"] += animal["food_yield"]
                    pawn["inventory"]["fiber"] += animal["fiber_yield"]
                    del wildlife[target]; add_event("hunt", target=target)
                continue
            if target in VISITOR_IDS:      # rob traveler; gentle pawns feel guilt
                dmg = max(1, 5 + pawn["skills"]["combat"] // 2)
                visitor = visitors[target]; visitor["hp"] -= dmg
                if visitor["hp"] <= 0:
                    plunder_inventory(pawn, visitor)
                    del visitors[target]; add_event("attack", plunder=True)
                    if pawn["personality"]["aggression"] < 6:
                        add_moodlet(pawn, "Guilt", -5, 15)
                else: visitor["state"] = "leaving"
                continue
            if target in RAIDER_IDS:       # fight off a scavenger
                dmg = max(1, 5 + pawn["skills"]["combat"] // 2)
                raider = raiders[target]; raider["hp"] -= dmg
                if raider["hp"] <= 0:
                    del raiders[target]; add_event("raid", action="slain")
                else: raider["state"] = "fleeing"
                continue
            dmg = max(1, 5 + pawn["skills"]["combat"] // 2 - target["skills"]["combat"] // 4)
            if "Brawler" in pawn["traits"] and pawn["gear"]["main_hand"] is None: dmg += 3
            target["vitals"]["hp"] = clamp(target["vitals"]["hp"] - dmg)
            if target["vitals"]["hp"] <= 0: target["status"] = "incapacitated"
        elif action == "Mate":
            if not legal_target(target): add_event("failed"); continue
            if target["sex"] == pawn["sex"] or _are_kin(pawn, target): continue
            if pawn_id not in target["partners"]:
                if pawn["relationships"].get(target, 0) < 25 or \
                   target["relationships"].get(pawn_id, 0) < 25: continue
            if random.random() < CONCEPTION_CHANCE:
                target["pregnant_ticks"] = PREGNANCY_TICKS
                target["partner_id"] = pawn_id
            pawn["partners"] = dedup(pawn["partners"] + [target])
            target["partners"] = dedup(target["partners"] + [pawn_id])
        elif action == "Interact":
            if flavor in SOCIAL_WORDS: pawn["vitals"]["morale"] += 5
            elif flavor in GATHER_WORDS: yield_tile_resource(pawn)
            elif flavor in CRAFT_WORDS: biome["shelter"] = min(100, biome["shelter"] + 3)
            elif flavor in RELAX_WORDS: pawn["vitals"]["energy"] += 10; pawn["vitals"]["morale"] += 3
            elif flavor in TAME_WORDS: try_tame_wildlife(pawn)
            elif flavor in RECRUIT_WORDS: try_recruit_visitor(pawn, target)
            elif flavor in FARM_WORDS: till_or_harvest_plot(pawn)
            elif flavor in PRAY_WORDS: monolith_oracle_prayer(pawn)
            else: pawn["vitals"]["morale"] += 3
        elif action == "Expedition":
            try_start_expedition(pawn, pawn_id, intents)
    # mental break resolution overrides intent when morale is 0
    if pawn.get("mental_break"):
        _resolve_break(pawn, pawn_id)

    # personal goals: adopt LLM wishes, advance on deeds, pay off when done
    if not pawn.get("goal") and new_goal:
        pawn["goal"] = adopt_goal(pawn, new_goal)
    for pid, p in world_state["pawns"].items():
        goal = p.get("goal")
        if goal and goal["progress"] >= goal["needed"]:
            p["vitals"]["morale"] += GOAL_MORALE     # +15 and skill XP
            add_event("goal", actor=pid, goal=goal["text"])
            p["goal"] = None                          # ready for the next wish
\end{lstlisting}

\begin{lstlisting}[style=python, caption={Tick Orchestration (core.py, condensed). lock $\to$ schema $\to$ LLM $\to$ override $\to$ resolve $\to$ environment $\to$ tick++ $\to$ save; season-change detection, eulogy, adoption DMs, the Architect review, and embed all run outside the lock}, label={lst:tick}]
async def run_tick():
    async with tick_lock:                              # serialises vs god commands
        TickResponse = schema.build_models()           # 1. roster-aware schema
        content, _ = await asyncio.to_thread(          # 2. structured LLM output
            _llm_call, SYSTEM_PROMPT, build_prompt(), TickResponse, 0.7)
        data = TickResponse.model_validate_json(content)
        events.add_event("world", description=data.world_event)
        dead_tick = state.world_state["tick"]          # capture before mutation
        # 3. Build intents; god orders override the LLM's proposal.
        intents = {}
        for pid, pawn in state.world_state["pawns"].items():
            if pawn["status"] != "active":
                continue
            decision = getattr(data, pid)
            action, target = decision.action, decision.target
            flavor = getattr(decision, "flavor", None)
            new_goal, new_title = getattr(decision, "new_goal", None), getattr(decision, "new_title", None)
            if action == "Move":
                target = decision.direction            # map direction -> target
            order = state.god_orders.get(pid)
            if order:
                action, target = order["action"], order.get("target")
                if action == "Interact": flavor = order.get("flavor") or flavor
            intents[pid] = (action, target, flavor, new_goal, new_title)
        tick_events = engine.resolve_actions(intents)  # 4. deterministic effects
        tick_events += engine.tick_environment()       #    world ages; may signal season change
        state.god_orders.clear(); state.god_whispers.clear()
        state.world_state["tick"] += 1                 # increment before save
        state.save_state(); events.log_to_jsonl()      # 5. persist
    # Lock released: god commands can run during the slow LLM/webhook I/O.
    if state.pending_chronicle:                        # season changed: write chronicle
        await _chronicle_season(state.pending_chronicle)
    if state.pending_monument:                         # monolith done: carve dedication
        await _inscribe_monument()
    await _eulogize_fallen(dead_tick)                  # LLM epitaph + eulogy embed
    await _notify_adopted(tick_events)                 # DM adopted pawns' milestones
    state.save_state()                                 # re-save after outside-lock calls
    if _is_milestone_tick(tick_events) or state.pending_chronicle:
        await asyncio.to_thread(post_to_discord, data) # milestone-only state embed + PNG map
    post_crisis(tick_events)                           # raid / wildfire / flood / miasma
\end{lstlisting}

\section{Expected Outcomes}

\subsection{Design Objectives}
The AI Director architecture is evaluated against four design objectives that follow from the constraints of a 2~GB container on HDD storage:

\begin{enumerate}
\item \textbf{Zero Memory Growth}: the prompt is bounded (fixed system prompt, history truncated to the last ten structured events) and the output schema caps the response size; because inference is off-host, no KV cache or model weights occupy container RAM and memory consumption remains flat indefinitely.
\item \textbf{Deterministic Boundaries}: the model emits only \emph{intent} (action, narrative, target); all numbers are produced by the engine and clamped to \([0,100]\), so hallucinated stats are structurally impossible.
\item \textbf{Enforced Intervention}: god orders are overridden in Python after the LLM responds, so intervention is guaranteed regardless of model compliance; failed intents (energy shortfall, self-attack, missing target) are logged as \texttt{failed} events.
\item \textbf{Agent Reactivity}: each agent sees the others' vitals, skills, relationships, and recent events, enabling emergent behaviours and grudges. Relationship deltas persist across ticks but fade several steps toward zero each dawn, so bonds and feuds both require real upkeep to endure. A successful \texttt{Mate} officially pairs two pawns (recorded in each other's \texttt{partners}; polygamy allowed), and children record their parents (\texttt{mother\_id}/\texttt{father\_id}); the engine blocks incest at the mate gate. A read-only family tree (\texttt{!tree}) renders couples (mutually partnered or with shared children), mate-eligible bonds, kin lines, and rivalries from these pairwise relationships. Each pawn carries a \texttt{generation} (founders are 1, offspring take the maximum parental generation plus one) and gravestones record the fallen pawn's generation, so the prompt can render a compact dynasty roll-up --- living and fallen per generation --- alongside the colony's cumulative deeds and any unclaimed ancestral heirlooms; when Generation 1 dies out, Generations 2 and 3 simply inherit the memory and carry the colony on. The completed monolith doubles as an oracle and rune archive: significant achievements (a tradition forged, a prophecy fulfilled, the first predator slain, the birth of a new generation, the fall of a beloved, titled, or elder ancestor) are carved as permanent runes on a capped archive, and a pawn who \texttt{Interact}s with a prayer verb at Camp receives divine inspiration ($+8$ morale and $+1$ XP in its weakest skill) and, in the cold, a \texttt{Divine Warmth} moodlet that shaves \texttt{MONUMENT\_WARMTH\_BLESSING} off the season's cold --- a literal weather warning with teeth. The ruins tile is the named remnant of The Sunken Tribe, and each Scout there carries a chance to unearth a fragment of forgotten history, an ancient tool blueprint (added to the colony's recipe list), or a carved warning that grants scouting insight and lifts colony morale; recovered fragments feed the prompt and the \texttt{!lore} view, keeping the lost civilization present in the world's living memory. Deeds also mint durable \emph{relational badges} --- \texttt{Lifesaver} (sharing food with a starving pawn), \texttt{Betrayer} (attacking a pawn bonded to you at 25+ relationship), \texttt{Indebted} (receiving a share), \texttt{Mentor} (teaching a tilemate), \texttt{Widow} (losing a partner) --- surfaced per pawn in the prompt so the Director can weave them into tick narratives, and queryable via \texttt{!badges}. Feuds cross generations: children are born seeded with their parents' rivalries (mutual relationships at or below \texttt{RIVAL\_THRESHOLD}), and mutual rivals who share the camp tile risk spontaneous \emph{camp brawls} (small damage and deeper hatred, rolled each tick at \texttt{BRAWL\_CHANCE}) --- so a new generation must actively choose peace (courtship, sharing food) or let the old hatred flare up again. The schema's \texttt{new\_title} field lets the Director bestow free-form earned roles (e.g.\ \emph{Fang-Breaker}, \emph{Keeper of the Hearth}, \emph{Seer of Whispers}); the engine validates them and buckets by keyword into subtle passive perks --- martial words shave \texttt{TITLE\_MARTIAL\_DEFENSE} off damage taken, nurturing words add \texttt{TITLE\_NURTURE\_SHARE} food to every share, and spiritual words halve Grief moodlet duration (\texttt{TITLE\_SPIRIT\_GRIEF\_DIV}) --- so invented titles carry mechanical weight without letting the LLM write stats. Once a year, alongside the Architect, a \emph{Camp Council} LLM (\texttt{COUNCIL\_PROMPT}, \texttt{COUNCIL\_INTERVAL}) reviews the year's history and names a recognized leader and a one-sentence Colony Mandate; the engine validates both, grants the leader a \texttt{Chosen} moodlet and morale, and the mandate leads every tick prompt so the whole colony shares a unified narrative focus (\texttt{!council}).
\end{enumerate}

\subsection{Behavioural Evaluation}
The following qualitative results were observed over continuous runs:

\begin{enumerate}
\item \textbf{Stable Long-Run Operation}: no OOM faults or state corruption occurred across extended runs; the 370-test offline suite (\texttt{tests/}) validates deterministic resolution, and state survived restarts via \texttt{terrarium\_state.json} while the structured event log (\texttt{terrarium\_log.jsonl}) grew append-only as the paper dataset.
\item \textbf{Enforcement Rate}: every illegal intent (energy shortfall, self-attack, missing/unknown target) was rejected by the engine and recorded as a \texttt{failed} event; at no point did a hallucinated stat alter the world, because the model never emits numeric deltas.
\item \textbf{Intervention Correctness}: \texttt{!order} always produced the commanded action even when the model proposed otherwise; \texttt{!say} influenced narrative flavour only, as designed.
\item \textbf{Emergent Dynamics}: relationship deltas after combat produced visible grudge cycles (repeated mutual attacks) in the event history, demonstrating that the model reads and reacts to the rendered relationship state.
\item \textbf{Environmental Pressure}: seasonal cycles (day/night, Summer heatwaves, Winter cold) and depletable wood/food stocks drove reactive behaviour: agents stockpiled wood before Winter, reinforced the shelter, and shared food during scarcity, without any hard-coded policy beyond the deterministic consequences.
\item \textbf{Negligible Host Load}: with inference off-host, CPU utilisation stays near \(0\%\) between ticks apart from network I/O, and container memory is flat at \(\approx\) 250~MB, ensuring no performance degradation for adjacent hypervisor guests.
\end{enumerate}

\section{Conclusion}
The proposed architecture confirms that hosted open-weight models such as Gemma 4 can act as autonomous decision engines for background game loops while keeping the host footprint minimal, a 2~GB container with no model resident in RAM. Decoupling \emph{intent} (LLM) from \emph{consequence} (deterministic engine) prevents state corruption, while per-tick schema rebuilds (validated by the 370-test offline suite) passed as structured-output schemas and a ring buffer of structured events keep long-running behaviour coherent. A two-way Discord interface makes the system observable and steerable by a human ``god'' without breaking the simulation's determinism, and the pure-Python PNG map renderer (\texttt{map\_renderer.py}, built on \texttt{struct} and \texttt{zlib}) keeps the zero-framework ethos. Future work may explore self-hosting Gemma 4 locally via Ollama for fully-offline runs, dynamic biome adaptation, and multi-modal feedback via image generation.

\subsection{Future Work: Roadmap}
The design remains a staged roadmap beyond the community/lore layer of Stage 3, the hazard/visitor layers of Stages 4--5, the megaproject/farming layer of Stage 6, the culture/ritual layer of Stage 7, the raid/defense layer of Stage 8, and the autonomous-world-engine layer of Stage 9. Each stage keeps the AI Director pattern --- the LLM proposes intent only, while pure-Python deterministic rules own all numbers, state stays flat, and every mechanic remains offline-testable:

\begin{enumerate}
\item \textbf{Stage 9 --- The Autonomous World Engine (Dynamic Synthesis \& Balance Patches)}: implemented. Inspired by VRMMO autonomous game masters, the engine gained dynamic recipe discovery (\texttt{custom\_recipes} checked alongside static \texttt{RECIPES}; synthesized blueprints craftable via \texttt{Build} at tiers 4--10 with per-resource costs and combat/woodcutting/scouting/fiber bonuses), procedural world prophecies with multi-tick quest tracking (\texttt{active\_quests}: hunt/chop/stockpile/survive kinds paying colony-wide morale and optional titles), and bounded tuning multipliers (\texttt{biome.modifiers} for regrowth/cold/spawn rates). Every \texttt{PATCH\_INTERVAL} (400 ticks, one year) an Architect LLM reviews the world outside the tick lock and emits a \texttt{PatchUpdate} (\texttt{patch\_title}, \texttt{balance\_changes}, bounded numeric deltas, optional \texttt{new\_recipe}/\texttt{new\_quest}); Python validates and strictly clamps every value to $[0.7, 1.3]$ regardless of LLM output, increments \texttt{patch\_version}, appends to a capped \texttt{patches} ledger, logs a \texttt{patch} event, and posts a formatted ``Terrarium Patch Notes vX.Y'' embed --- all without rewriting raw \texttt{.py} code, keeping the deterministic engine as the sole source of truth.
\item \textbf{Stage 10 --- Persistent Narrative Memory (future)}: colony-authored artifacts (murals, journals, spoken legends) persist as physical world objects that seed future prompts, and an LLM-arbitrated ``World Soul'' council votes on each annual patch's direction, deepening autonomy while keeping numeric consequences inside the deterministic engine.
\end{enumerate}

\appendix
\section{Appendix A: Legacy Monolithic Implementation}
For contrast, Listing~\ref{lst:legacy} reproduces the initial single-file prototype that preceded the modular AI Director design. In this version the LLM emitted numeric deltas (\texttt{hp\_change}, \texttt{energy\_change}) directly, so state integrity depended entirely on model compliance; the refactor described in this paper eliminates that risk by moving all numbers into the deterministic engine.

\begin{lstlisting}[style=python, caption={Legacy Monolithic Loop (superseded --- LLM emitted \texttt{hp\_change}, \texttt{energy\_change} deltas directly)}, label={lst:legacy}]
import json
import time
import requests
from ollama import chat
from pydantic import BaseModel, Field
from typing import List, Optional

# ------------------ CONFIG ------------------
DISCORD_WEBHOOK_URL = "https://discord.com/api/webhooks/YOUR/WEBHOOK"
MODEL_NAME = "qwen2.5:0.5b"
TICK_INTERVAL_SECONDS = 60
MAX_HISTORY = 3   # ring buffer size

# ------------------ PYDANTIC SCHEMAS ------------------
class AgentDecision(BaseModel):
    action: str = Field(description="Action name (e.g., Chop, Rest, Scout, Attack)")
    narrative: str = Field(description="1-2 sentence description")
    hp_change: int = Field(description="HP delta (-10 to +10)", ge=-10, le=10)
    energy_change: int = Field(description="Energy delta (-10 to +10)", ge=-10, le=10)

class TickResponse(BaseModel):
    world_event: str = Field(description="Global status update")
    pawn_1: AgentDecision
    pawn_2: AgentDecision

# ------------------ INITIAL STATE ------------------
world_state = {
    "tick": 1,
    "history": [],   # ring buffer
    "pawns": {
        "pawn_1": {"name": "Lumberjack", "hp": 100, "energy": 80},
        "pawn_2": {"name": "Scout", "hp": 90, "energy": 50}
    }
}

SYSTEM_PROMPT = """You are the narrator of a digital terrarium.
Rules:
- Pawns can Chop, Rest, Scout, or Attack each other.
- HP and Energy are bounded 0-100.
- The Lumberjack is sturdy but slow; the Scout is fragile but quick.
- Return ONLY valid JSON matching the required schema."""

def build_prompt():
    p1 = world_state["pawns"]["pawn_1"]
    p2 = world_state["pawns"]["pawn_2"]
    history_text = " | ".join(world_state["history"]) if world_state["history"] else "The terrarium is calm."
    return f"""
Recent history: {history_text}
Current status:
- Lumberjack: HP={p1['hp']}, Energy={p1['energy']}
- Scout: HP={p2['hp']}, Energy={p2['energy']}
Decide actions for both pawns.
"""

def mutate_state(data: TickResponse):
    for pawn_id, decision in [("pawn_1", data.pawn_1), ("pawn_2", data.pawn_2)]:
        pawn = world_state["pawns"][pawn_id]
        pawn["hp"] = max(0, min(100, pawn["hp"] + decision.hp_change))
        pawn["energy"] = max(0, min(100, pawn["energy"] + decision.energy_change))
    world_state["history"].append(data.world_event)
    if len(world_state["history"]) > MAX_HISTORY:
        world_state["history"].pop(0)

def post_to_discord(data: TickResponse):
    p1, p2 = world_state["pawns"]["pawn_1"], world_state["pawns"]["pawn_2"]
    embed = {
        "title": f"Terrarium Tick #{world_state['tick']}",
        "description": data.world_event,
        "fields": [
            {"name": f"Lumberjack (HP {p1['hp']} | Energy {p1['energy']})",
             "value": f"*{data.pawn_1.narrative}* (Action: {data.pawn_1.action})",
             "inline": False},
            {"name": f"Scout (HP {p2['hp']} | Energy {p2['energy']})",
             "value": f"*{data.pawn_2.narrative}* (Action: {data.pawn_2.action})",
             "inline": False}
        ],
        "footer": {"text": f"History: {' -> '.join(world_state['history'][-3:])}"}
    }
    try:
        requests.post(DISCORD_WEBHOOK_URL, json={"embeds": [embed]}, timeout=5)
    except requests.exceptions.RequestException:
        pass   # graceful fail

def run_tick():
    print(f"Tick {world_state['tick']} starting...")
    try:
        response = chat(
            model=MODEL_NAME,
            messages=[
                {"role": "system", "content": SYSTEM_PROMPT},
                {"role": "user", "content": build_prompt()}
            ],
            format=TickResponse.model_json_schema()
        )
        data = TickResponse.model_validate_json(response.message.content)
    except Exception as e:
        print(f"LLM error: {e}")
        world_state["tick"] += 1
        return
    mutate_state(data)
    post_to_discord(data)
    world_state["tick"] += 1

if __name__ == "__main__":
    while True:
        run_tick()
        time.sleep(TICK_INTERVAL_SECONDS)
\end{lstlisting}
