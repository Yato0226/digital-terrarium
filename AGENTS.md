# AGENTS.md

LLM-driven "digital terrarium" simulation: Gemma (hosted via the Gemini API) narrates, Discord lets a "god" intervene. Single-package Python app, no framework.

## Commands

- Verify everything: `ruff check . && python -m pytest tests -q` (370 tests, fully offline — no API/Discord needed; tests never import `llm.py`).
- Syntax check a single file: `python -m py_compile <file>.py`.
- Run the live bot: `python main.py` — requires `.env` with `DISCORD_BOT_TOKEN` (and webhook if embeds wanted) plus a `GEMINI_API_KEY` from Google AI Studio. No local Ollama. Bot needs **Message Content Intent** enabled in the Discord Developer Portal.
- Auto-start on the LXC: `deploy/terrarium.service` (systemd, `Restart=always`, SIGINT for clean state save) → copy to `/etc/systemd/system/`, `systemctl daemon-reload && systemctl enable --now terrarium`, logs via `journalctl -u terrarium -f`. `WorkingDirectory` must be the project dir (state/log/.env are relative paths). On Proxmox also set **LXC → Options → Start at boot** so the bot returns when the host powers on.
- Config is `config.py` (env vars via `.env`/python-dotenv), not hard-coded.
- **Use subagents for exploration & verification**: when you need to survey the codebase, locate symbols, or cross-reference `todo.md` checkboxes against module diffs, delegate to `explore`/`general` subagents in parallel instead of reading whole files in the main thread. Keep the main thread for editing, running the verify commands, and deciding.

## Architecture (read before editing)

- **The LLM proposes intent only.** Output schema (`schema.py`, rebuilt each tick for active pawns) is `{action, narrative, quote, inner_monologue, direction, target, flavor, new_goal}`. **Never** let the LLM send stat numbers.
- **`engine.py` is the sole source of truth for consequences**: action costs (`ACTION_COSTS`), combat, skill XP, relationships, incapacitation/recovery, crafting, mental breaks, environmental death. Changing mechanics means editing `engine.py` — not prompts or schema.
- **Flow:** `core.run_tick()` → build schema → LLM → build intents (god orders override; Move maps `direction` into the intent) → `engine.resolve_actions()` → `engine.tick_environment()` (metabolism/seasons/weather/campfire/regrowth/break counters/aging/death→graveyard) → events → `tick += 1` then save (persists the advanced tick — never increment after save) → **lock released** → eulogy LLM + Discord embed run outside the lock.
- **LLM provider is `llm.py`** (hosted Google Gemini API, no local model): `generate_with_fallback(system, user, schema_model, temperature)` tries `GEMINI_MODEL` (`gemma-4-31b-it`) then `GEMINI_FALLBACK_MODEL` (`gemma-4-26b-a4b-it`), returning `(text, model_used)`. Ticks pass the per-tick Pydantic model as `response_schema`; eulogies call it with `schema_model=None` (freeform prose). Free-tier quotas: 30 RPM / 16K TPM / 14.4K RPD (reset midnight Pacific) — a 60s tick uses ~10% of the daily RPD. **On hosted Gemma the `response_schema` is what forces clean JSON and disables the thinking channel** (`response_mime_type` alone is ignored); `thinking_level="MINIMAL"` is set as an extra guard. If you hit the SDK 500 "alias" bug on a Gemma model, prefix the model id with `models/` (e.g. `models/gemma-4-31b-it`).
- Actions are exact strings `"Chop" | "Rest" | "Scout" | "Attack" | "Forage" | "Build" | "Share" | "Move" | "Mate" | "Interact"`. `target` is only valid for Attack, Share, or Mate (Attack/Share same-or-adjacent tile, Mate same tile); `direction` (N/S/E/W) only for Move; `flavor` (any free-form verb) only for Interact; engine rejects missing/self/down/unknown/far targets.
- **Free-form `Interact` + personal goals** (the "Rimworld freedom" layer): `Interact` (cost 5) takes any verb in `flavor`; `_do_interact` in `engine.py` buckets it by keyword into safe effects — social (morale +5, ±10 relationship with a same-tile pawn), gather (small tile-gated yield from Meadow/River/Forest/Quarry/Ruins), craft (shelter +3 at Camp or morale), relax (+10 energy/+3 morale), train (+1 combat XP), default (+3 morale). `!order X Interact <verb>` is a god order. Goals: `pawn["goal"]` is `None` or `{kind, resource?, target_id?, needed, progress, text}`; the LLM proposes one per pawn via `new_goal` ("gather 10 wood", "befriend Chief", "survive 5 days") and `engine._adopt_goal` parses it into a kind (`gather{resource}`, `social{target_id}`, `build`, `survive{needed=days×TICKS_PER_DAY}`); `_goal_nudge` advances it on matching deeds (Chop/Forage/Scout/Share/Build/Interact; survive ticks in `tick_environment`); `_complete_goal` pays +15 morale, skill XP (`GOAL_SKILLS`), and a `goal` event, then clears it so the LLM can propose the next one. All numbers live in `engine.py`.
- The world is a fixed 5×5 grid (`state.DEFAULT_GRID`, `world_state["grid"]`): Camp (2,2), Forest on the edges, Meadow/River for forage, Ruins (rich, risky scout), Quarry (stone). Chop/Forage/Build are tile-gated; a lit campfire warms only within Manhattan distance 1 of Camp. Pawns carry `pos [x,y]` and `engine.render_grid()` draws the emoji map.
- The shared `world_state["biome"]` block (`season`, `weather`, `day`, `campfire`, `shelter`, `wood_stock`, `food_stock`, `granary`, `palisade`) ages in `engine.tick_environment()` — it is never modified by prompts or schema. Environment constants (season length, drain rates, regrowth) live in `engine.py`.
- **Stage 2 fauna (`world_state["wildlife"]`, all logic in `engine.py`):** non-pawn entities from the `WILDLIFE` table (`Deer`/`Rabbit` = prey, `Wolf`/`Bear` = predator; each `{emoji, kind, hp, food_yield, fiber_yield, bite_damage}`). `tick_environment` spawns them season-gated (Winter/Autumn → predators, Spring/Summer → prey, cap `WILDLIFE_MAX`=3) and runs deterministic AI: prey flee the nearest pawn within Manhattan 2 and despawn with a `PREY_DESPAWN_CHANCE` (0.1) per tick once they've survived one tick (fresh spawns and tamed pets exempt); predators stalk the pawn furthest from Camp and **bite to incapacitate, never kill** (consistent with combat). Kills via `_do_attack` convert to `food` + `fiber` (no "meat" resource); `schema.target` extends to `pawn_ids + wildlife_ids`. `Interact` with a `tame`/`feed` flavor makes a skill-based tame roll (`0.5 + scouting*0.02`) → pet at Camp (camp-wide `PET_MORALE_BONUS`=+2 in `_metabolize`); `render_grid` draws 🦌/🐺 markers. **Granary** (`biome["granary"]` flag) stops Summer `food_stock` decay; **Palisade** (`biome["palisade"]`, max `PALISADE_MAX`=3) reduces predator spawn chance; both upgrade via `Build`. God view: `!wildlife` lists fauna.
- **Adding a stat/resource touches all of:** `state.make_pawn` + `state._migrate_pawn` (old saves auto-migrate), `state.DEFAULT_BIOME` for biome fields, `prompts.build_prompt`, `engine` resolution, `core.post_to_discord`, and optionally `bot.god_edit`. Adding an **action** touches `schema.ACTIONS` (Literal) and `engine.ACTION_COSTS` in lockstep — `bot.order`'s whitelist derives from `engine.ACTIONS`, so it follows automatically.

## State & persistence

- `world_state` in `state.py`: `{tick, history, biome, graveyard, grid, pawns, wildlife}`. Pawn shape is nested (`vitals.hp`, `inventory.{wood,food,stone,fiber}`, `gear.{main_hand,body}`, `counters.*`, `title`, `job`, `sex`, `pregnant_ticks`, `child_ticks`, `pos`, `mental_break`, `skills.*`, `relationships.*`, `status`, `goal`, lineage `mother_id`/`father_id`/`partner_id`, and `partners`), not flat. `biome` holds shared environment state (`season`, `weather`, `day`, `campfire`, `shelter`, `wood_stock`, `food_stock`, `granary`, `palisade`); `grid` holds the 5×5 tile map; `wildlife` is a top-level list of non-pawn entities (`{id, species, pos, state, hp, spawn_tick, tamed_by}`). Environmental death (Blizzard freeze, `starving_ticks > 5`, or old age) removes a pawn into `graveyard` snapshots (`{id, name, title, cause, died_tick, born_tick, epitaph}`) — combat 0 HP stays recoverable `incapacitated`.
- Tools are crafted via the Build action at Camp (auto-crafts the highest-tier affordable item from `engine.RECIPES`): Stone Axe (3W+2S, doubles Chop), Flint Spear (2W+1S, +4 Attack), Warm Coat (5F, +4 insulation). Stone comes from the Quarry/Ruins scout; fiber from Meadow forage.
- Mental breaks: morale ≤ 0 starts a 3-tick break by personality (aggression ≥6 → berserk, bravery ≤3 → paranoid, else apathetic; a **Pyromaniac** always breaks as `firesetter` — douse the campfire (−10), else burn 2 wood, else damage the shelter (−5)); `resolve_actions` forces the break behaviour and `tick_environment` counts it down.
- **Traits & moodlets (deterministic psychological layers):** `pawn["traits"]` is a `list[str]` rolled by `state.make_pawn`/`_give_birth` (`TRAITS` pool; founders are fixed — Lumberjack = Brawler, Scout = Night Owl). **Never proposed by the LLM**; all effects live in `engine.py`: `_pay_cost` halves Night Owl action costs after dark; `_do_attack` gives Brawlers +3 unarmed damage (and `_metabolize` −5 morale while wielding a non-melee tool like the Stone Axe — a spear is fine); Pyromaniacs get +5 morale near a lit fire; Pacifists refuse Attack (`failed`/`pacifist`) and get +2 gather yield; Iron Stomach halves hunger drain. `_inherit_traits` passes one trait per parent (50% each) at birth. `pawn["moodlets"]` is an **additive layer** over the direct-morale system: `[{name, delta, ticks_left}]`, decayed+summed each tick in `_metabolize` via `_tick_moodlets` (`MOODLET_GRIEF` on every death in `_kill`, `MOODLET_FROSTBITE` when warmth hits 0). Don't refactor the `_clamp(v["morale"]...)` system into moodlets.
- **Director hints:** `state.failed_intents` (transient, like `god_orders`; cleared in `reset_world`) counts consecutive feasibility failures (`engine.FEASIBILITY_REASONS`); `resolve_actions` → `_record_feasibility` records them (god orders are exempt). After ≥2, `prompts.build_prompt` appends a `Director note:` telling the LLM why the action failed. Any success clears the counter.
- Reproduction: pawns carry `sex` (M/F). `Mate` (cost 10) succeeds only on the same tile with an opposite-sex active pawn where the bond is **mutual** — both the suitor's relationship to the target and the target's to the suitor ≥ 25 (`MATE_RELATIONSHIP`); a starving female can't conceive and the colony caps at `MAX_PAWNS` (10). Relationships drift 5 steps toward 0 each dawn (`RELATIONSHIP_DECAY`, once per ingame day in `tick_environment`), so bonds need real upkeep — a +25 Share evaporates in five days of no contact. A **successful Mate makes the pair official**: both are added to each other's `partners` list (polygamy allowed, deduped), and partners skip the mutual-25 gate for future Mates — no re-earning the bond. The father is pinned to the mother at conception (`partner_id`); close kin — siblings, half-siblings, or parent↔child — are blocked by `_are_kin` (`too_close_kin`). On a 50% roll the female gains `pregnant_ticks` (20 = 1 day); `tick_environment` counts pregnancy down and calls `_give_birth` (newborn: weaker HP/energy, `child_ticks` 40 = 2 days before it can mate, auto name/job/sex from the state pools, and `mother_id`/`father_id` recorded; `partner_id` is cleared only on actual birth, so it survives cap-delays). Children can't court or be courted; a birth that comes due while the colony is at cap re-delays the pregnancy rather than losing it. `_kill` removes the dead pawn from everyone's `partners` (widows are free to court again). `engine.render_family_tree()` renders 💞 **couples** (mutual `partners` match **or** shared kids — lineage beats current bond), a 🤝 **bonded** tier (mutual ≥ 25 but not partners: mate-eligible friends, not couples), kin lines, and rivals (mutual ≤ `RIVAL_THRESHOLD` = −25), looking dead parents up in the graveyard (🪦); the god view is `!tree`.
- Aging: age is derived (`tick - born_tick`, no stored field — `engine.age_of`/`engine.is_elder`; `TICKS_PER_DAY` = `DAY_CYCLE` = 20, one sim day per 20 ticks — display/LLM-facing ages use `tick // TICKS_PER_DAY`). At `ELDER_AGE` (200 = 10 days) a pawn becomes an elder: `_metabolize` drains +1 energy/+1 morale per tick, `_do_rest` heals −5 less, and `_update_titles` names them "the Ancient". `_death_cause` adds old age after the blizzard/starvation checks — 2% per tick once elder, guaranteed at `OLD_AGE_MAX` (320 = 16 days).
- `terrarium_state.json` auto-saved each tick and on god commands; auto-loaded/migrated on startup.
- `terrarium_log.jsonl` — append-only structured event log (the paper dataset). Events are dicts `{tick, type, actor, target, data, description}`; `history` is a ring buffer (`MAX_HISTORY=10`).
- **Stage 3 community/lore:** `world_state["chronicle"]` is a capped (`state.MAX_CHRONICLE`=24) list of `{season, title, text, tick}`; on a season change `tick_environment` sets the transient `state.pending_chronicle` (like `god_orders`; cleared in `reset_world`), and after the lock releases `core.run_tick` calls `core._chronicle_season(season)` — an outside-lock LLM call (`schema_model=None`) that writes the title/paragraph and emits a `"chronicle"` event (the god view is `!chronicle`). `world_state["heirlooms"]` is a list of `{id, name, stat_bonus, moodlet_delta, source}` (+ `owner` once claimed): `_kill` drops one when a **titled** pawn dies holding a `main_hand` tool (tool→`stat_bonus` map in `engine.HEIRLOOM_BONUS`); `_do_interact`'s `heirloom` bucket (`claim`/`inherit`/`bequeath`/`receive`) claims it by name (else first unclaimed), grants the skill via `_gain_skill` and a `Proud` moodlet; the owner is released if the holder dies; `!list`/prompt pawn lines show owned heirlooms via the 🏆 tag (`!heirlooms` lists all). `world_state["adoptions"]` maps `discord_user_id` → `pawn_id` (persisted, loaded in `load_state`): `!adopt`/`!unadopt`/`!my` (any channel, no god gate) manage it; after each tick `core._notify_adopted(tick_events)` scans for `birth`/`goal`/`break`/`death` events and calls the `core.notifier` hook (async `(user_id, message)`, registered by `bot.on_ready` → gateway DM via `_dm_adopter`; webhooks can't DM). **`engine.py` stays pure — no Discord logic.** `map_renderer.py` is a pure-Python PNG writer (zlib/struct, no Pillow): `map_renderer.render_png()` draws the grid + pawns + wildlife; `core.post_to_discord` attaches it via multipart (`attachment://map.png`) and falls back to the ASCII grid (the embed field) when there's no webhook or the render fails.
- `.env`, `terrarium_state.json`, `terrarium_log.jsonl` are gitignored — never commit secrets.

## Concurrency (easy to break)

- `core.tick_lock` serializes ticks and state mutation. **Any Discord command that mutates `world_state` must wrap its body in `async with core.tick_lock:`** (see `bot.py`). `run_tick` holds the lock only for deterministic mutation + save, then releases it for the eulogy LLM and Discord webhook so god commands aren't stalled by network I/O.
- `pause_event` gates the scheduler; single `tick_loop` task is created in `bot.on_ready` with a reconnect guard — don't add a second one. Extinction is durable: `_notify_extinction` sets `world_state["extinct"]` (persisted) and clears `pause_event`; `load_state` keeps a dead world with a graveyard instead of force-respawning it.

## Gotchas

- **Python 3.10** (not 3.11+): `Literal[*ids]` unpacking is unavailable — use `Literal[tuple(pawn_ids)]` (valid per PEP 586) in `schema.py`.
- Roster changes are reflected by the schema being rebuilt every tick — no schema edits when adding/removing pawns.
- Tests reset the world and set `events.LOGGING = False` via the `fresh_world` fixture; run `resolve_actions` against `state.world_state["pawns"]` directly.
- The god `!say` is a whisper in the prompt **and** grants +15 morale (a god effect applied in `bot.say`); `!order` is enforced by the engine override. Don't blur these.

## Roadmap (implemented through Stage 8; checklist in `todo.md`)

Stage 1 (traits, moodlets, director hints), Stage 2 (fauna/wildlife), **Stage 3 (community/lore)**, **Stage 4 (dynamic hazards/tiles)**, **Stage 5 (visitors)**, **Stage 6 (megaprojects & farming)**, **Stage 7 (culture & rituals)**, and **Stage 8 (bandits & raids)** are **implemented** — documented in Architecture/State above and in `paper.tex`. `todo.md` is the **canonical checklist** for all stages and cross-stage verification — read it, and update its `[ ]` boxes when you land a stage; never treat it as a static artifact. Stage 9 (the autonomous world engine) is listed there as an unchecked item. Design conventions (apply when implementing future stages):

- **Stage 3 — Community/lore (implemented)**: the seasonal chronicle is an async LLM call **outside the tick lock** (clone of `_eulogize_fallen`, `schema_model=None`). Heirlooms drop from titled dead pawns' `main_hand` in `_kill` and are claimed via Interact. `world_state["adoptions"]` maps user IDs → pawn IDs; notifications live in `core` (a notifier hook registered by `bot.on_ready`, since webhooks can't DM) — **`engine.py` stays pure, no Discord logic**. The map renderer is a pure-Python PNG writer (zlib/struct, no Pillow) to keep the zero-framework ethos.
- **Stage 5 — Visitors (implemented)**: `world_state["visitors"]` holds transient NPCs (`state.make_visitor`, ids `visit_N`); `tick_environment` spawns one at the grid edge every `VISITOR_INTERVAL` (150) ticks and runs the `arriving → visiting (3–5 ticks) → leaving` state machine (`_step_visitors`). Kinds live in `engine.VISITOR_TYPES` (Merchant/Wanderer/Bard). The schema `target` literal extends to visitor ids; `_do_share` → `_share_with_visitor` barters, `_do_mate` → `_court_visitor` and `_do_interact`'s `recruit` bucket roll `0.3 + sociability×0.05` to recruit via `_recruit_visitor` (respects `MAX_PAWNS`), and `_do_attack` → `_attack_visitor` plunders + applies a `Guilt` moodlet to pawns with aggression < 6. `!visitors` is the god view; `render_grid`/`core._visitors_txt`/`prompts` show them.
- **Stage 6 — Megaprojects & farming (implemented)**: `world_state["monument"]` (`{wood, stone, done, inscription}`) is a top-level key (not in `DEFAULT_BIOME` — the shallow `dict(DEFAULT_BIOME)` copy in `reset_world` would alias a nested dict). Once shelter/fire at 100, granary built, and palisade maxed, `_do_build`'s post-palisade branch consumes 5 wood + 5 stone per action (capped at `MONUMENT_WOOD_NEEDED` 20 / `MONUMENT_STONE_NEEDED` 15); completion sets the transient `state.pending_monument` (like `pending_chronicle`, cleared in `reset_world`) so `core._inscribe_monument` runs an outside-lock LLM dedication. Effects live in `_metabolize`: morale floor `MONUMENT_MORALE_FLOOR` (10, applied after moodlets/traits so morale-driven breaks can't trigger) and `MONUMENT_INSULATION` (+2 warmth only within `CAMP_RANGE`). `!monument` is the god view. **Farm Plots** ride the Stage 4 `tiles` overlay (`{"farm": ticks}`, `FARM_TILE` 🌾 replaces the 🫐 grid cell): `_do_interact`'s `farm` words bucket (`till`/`plant`/`farm`/`harvest`/`crop`…) tills a Meadow or harvests a ripe plot (guaranteed `FARM_HARVEST_FOOD` 15 + `FARM_HARVEST_FIBER` 5 into the pawn's inventory — never touches `biome["food_stock"]`), and `_grow_farms` (called in `tick_environment`) advances plots +1/tick only in `FARM_GROW_SEASONS`, firing a one-shot `farm_ready` event at `FARM_GROW_TICKS` (20); harvest resets the plot to 0 so it regrows.
- **Stage 7 Part 1 — Emergent traditions (implemented)**: `world_state["traditions"]` (`{tag, predators_slain, trees_felled, rations_shared}`) is a top-level key holding **colony-wide cumulative counters that survive pawn deaths** — incremented in `_do_chop` (`trees_felled`), `_do_attack` predator kills (`predators_slain`), and `_do_share`/`_share_with_visitor` (`rations_shared`). `_evaluate_tradition()` runs on season change in `tick_environment` and stamps the first threshold crossed (strictly `>` `HUNTERS_THRESHOLD` 10 / `FORESTERS_THRESHOLD` 100 / `KINDRED_THRESHOLD` 20, Hunters > Foresters > Kindred priority); tags are **sticky** — a set tag is never re-evaluated. Effects all live in `engine.py`: Hunters = `HUNTERS_COMBAT_XP` (2) XP per hunting kill via doubled `_gain_skill` + `HUNTERS_COLD_REDUCTION` (1) subtracted in `_metabolize` after the Warm Coat; Foresters = `FORESTERS_CHOP_BONUS` (+1 wood) in `_do_chop` + `_shelter_damage(amount)` halves the only shelter degradation paths (fire `CAMP_BURN_SHELTER`, berserk/firesetter breaks); Kindred = `KINDRED_SOCIAL_MORALE` (+8) in `_do_interact`'s social bucket. There is no natural shelter decay — "degrades slower" means the damage events halve. `!tradition` is the god view; `prompts.build_prompt` shows the tag (or live counters toward one); `core._biome_infra_txt` embeds it in the Discord embed.
- **Stage 7 Part 2 — Festivals & funerary rites (implemented)**: `_seasonal_feast()` runs inside `tick_environment`'s season-change block when `new_season in FEAST_SEASONS` (Winter/Summer) — gated on `biome["food_stock"] > FEAST_FOOD_REQUIRED` (15), it costs `FEAST_FOOD_COST` (5) and gives every active pawn `FEAST_MORALE` (+15) plus a `Festive` moodlet (`FESTIVE_MOODLET_DELTA` +5, `FESTIVE_MOODLET_TICKS` 15). Funerary rites: `_kill` records `"beloved"` on the graveyard snapshot via `_is_beloved(pawn_id, pawn)` — true when the fallen pawn's average relationship to living pawns ≥ `BELOVED_RELATIONSHIP` (25). `INTERACT_WORDS["rite"]` (`bury`/`mourn`/`eulogiz`/`grieve`/`lament`/`funeral`/`wake`/`honor`/`remember`) routes `_do_interact` → `_do_funerary_rite`: requires the pawn on `RITE_TILES` (`BUILD_TILE` or `RUIN_TILE`), and with a beloved in the graveyard halves (`max(1, //2)`) every `Grief` moodlet on same-tile active pawns (event `"rite"`); without a beloved it falls back to the +3-morale default interact. `!graveyard`/prompt `fallen_line` mark beloved entries 💖. Old saves tolerate missing `beloved` via `.get("beloved", False)`.
- **Stage 8 — Scavenger raids (implemented)**: `world_state["raiders"]` holds hostile NPCs (`state.make_raider`, ids `scavenger_N`). In `tick_environment`, an Autumn raid spawns 1–2 raiders at a random grid edge when the colony holds ≥ `RAID_WEALTH_THRESHOLD` (30) combined food+wood and none are already about (`tick % RAID_INTERVAL` 100 gate). `_step_raiders` runs the `marching → fleeing` state machine: marching raiders `_walk_toward` Camp greedily, slowed by the Palisade (`slowed = palisade` ticks between moves); on the camp tile `_raid_defense` sums tamed-predator bite damage + the highest-combat pawn's strike (`RAID_DEFEND_DAMAGE` 4 + combat//2, + spear) — a raider damaged there is repelled before stealing, killed at ≤0 HP — otherwise `_raid_steal` takes `RAID_STEAL` (5) food from `food_stock` first, then pawn rucksacks, then it flees; fleeing raiders walk to the nearest edge and despawn with a `fled` event. `_do_attack` handles `scavenger_` targets (damage sets `fleeing`, death removes); schema `target` extends to raider ids; `render_grid` marks them 🥷; `!raiders` is the god view; `prompts`/`core._raiders_txt` show them.
- **Stage 9 — Autonomous world engine (implemented)**: an **Architect LLM** tunes the world without code edits. `state.py` holds the registries — `biome["modifiers"]` (`{"regrowth": 1.0, "cold": 1.0, "spawn": 1.0}`, `dict(DEFAULT_MODIFIERS)`) plus `world_state["custom_recipes"]`, `["active_quests"]`, `["patch_version"]` (`"v1.0"`), and `["patches"]` (capped `state.MAX_PATCHES` 8) — all backfilled in `load_state`, so old saves load cleanly. **`default_biome()`** (fresh `modifiers` copy) replaces the bare `dict(DEFAULT_BIOME)` shallow copy in `reset_world`/`load_state`/the module default — mutating one reset's modifiers must never alias the next (this bit us in tests). Quest entries carry `{id, title, text, kind, needed, progress, reward_morale, reward_title?, created_tick}`; kinds are `hunt`/`chop`/`stockpile`/`survive`. Engine logic (all in `engine.py`): `_all_recipes()` merges static `RECIPES` + `custom_recipes` normalized to `{materials, slot, tier}`; `_try_craft` picks the highest-tier affordable blueprint (custom recipes use `slot`); `_custom_tool_bonus(pawn, key)` sums synthesized bonuses for combat/woodcutting/scouting/fiber across both gear slots — wired into `_do_attack` (4 damage expressions), `_do_chop`, and `_do_forage` (also skips the Brawler tool-morale penalty when the pawn wields a synthesized weapon); `_colony_resource(resource)` sums active rucksacks; `_quest_progress(kind, actor, **tags)` advances matching quests, `_complete_quest` pays colony-wide morale + optional `reward_title`, clears the quest, and emits `quest_complete`; `_check_quests()` (called in `tick_environment`) evaluates `survive` (days elapsed) and `stockpile` (rucksack total). Balance multipliers: `_modifier(key)`/`_clamp_modifier(v)` (clamped `[MODIFIER_MIN 0.7, MODIFIER_MAX 1.3]`) applied to regrowth (`max(0, round(growth * mod))`), cold (`round(cold * mod)` in `_metabolize` before Coat), and spawn (outer 0.3 gate, `pred_chance`, prey 0.3). The Architect (`core._run_architect`, outside the lock every `engine.PATCH_INTERVAL` 400 ticks): `schema.build_patch_model()` → `engine.apply_patch(deltas)` (strict clamp, returns old/new) → `validate_new_recipe`/`validate_new_quest` (safe coercion, caps, dedupe) → `bump_patch_version()` (`v1.0`→`v1.1`) → `"patch"` event + `patches.append` + `post_patch_notes` embed. God views: `!recipes`, `!quests`/`!prophecies`, `!patchnotes` (via `core.recipes_txt`/`core.quests_txt`/`core.patchnotes_txt`). `config.ARCHITECT_TEMPERATURE` (0.8). Quest/recipe validation lives in `engine.py` so the whole Stage 9 surface is offline-testable without `llm.py`.
- Each stage still touches the full "adding a stat" list (state + migration + prompts + engine + `core.post_to_discord` + optionally `bot.god_edit`) and must stay in sync with `paper.tex`, `README.md`, and this file.

## Development workflow (Stages 4+)

- Work **stage by stage**; **push at each stage boundary** (never mid-stage unless asked).
- Land each stage **in parts** — one `todo.md` checkbox / sub-section per part; don't batch a whole stage into a single change.
- Every part follows **implement → test → commit**: write the code + tests, run `ruff check . && python -m pytest tests -q` (and `python -m py_compile` on touched files), then commit that tested chunk *before* starting the next part.
- Commit messages name the part and the stage (e.g. `Stage 4: wildfire tile lifecycle`); commit `todo.md` alongside the code it describes, ticking the boxes as each part lands.
- **Keep `README.md` in sync** whenever new Discord commands or player-facing features land: update the god-commands table (`README.md` §God commands) and any feature/run instructions in the same part/commit as the code that introduces them. `README.md` tends to drift — treat it like `paper.tex`: same stage, same commit.

**Verifying the checklist with subagents:** `todo.md` is untracked, so `git diff todo.md` shows nothing — the checklist is the cross-reference target itself, so read it directly first. To check whether a marked `[x]` is really implemented, delegate the cross-referencing to **subagents in parallel**: one per touched module (`engine.py`, `state.py`, `prompts.py`, `schema.py`, `core.py`, `bot.py`, `map_renderer.py`). Give each subagent the exact `todo.md` checkbox texts for its module plus the instruction to run `git diff <module>.py` (or `git log -p` for already-committed stages) and report back "implemented / over-claims" with line references — don't read the full files one by one in the main thread. Collect the reports, then either fix the code to match the spec or uncheck the box. Batch independent checks (ruff + pytest, py_compile per file, paper sync) the same way.
